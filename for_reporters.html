For reporters and researchers: what you can and cannot say

Every number on this site started as a person: someone who didn't come home from a crossing, a market, a bus stop. I built this to make those numbers easier to find and harder to ignore. I also know that a careless sentence built on them can do harm, to families, to neighbourhoods, and to the argument for fixing these roads. So here, plainly, is how far you can trust each part.

This site is a compilation. It is not a primary source. Whatever you publish, please name the original agency report (each dataset's manifest says which one) and link here only as the copy you can trace.

Solid: cite the original report

District crime and road-safety figures, 2016–2024

  • These come from NCRB and the Delhi Traffic Police crash reports. I checked them against the sources, and every correction since August 2026 is written down in the data changelog.
  • The 2024 crash-prone zone rankings and counts are copied from the Delhi Road Crash Report tables, row for row.
  • A zero in a survey-based layer can simply mean nobody surveyed there. Read the coverage note before you write that a district has none.

A safe way to say it: “According to the Delhi Road Crash Report 2024, …”

Leads only: verify before publishing

Locations, land use and mapped infrastructure

  • Where a crash zone sits on the map is my best guess from its name, and it can be 250 m to a kilometre out. These are not police geotags. Please write “in the area of”, never “at this spot”. A family may live at that spot. (how I checked)
  • Master Plan 2047 against the satellite shows where the plan and the 2021 land cover disagree. A satellite sees what covers the ground, not what the building is used for, so a gap is a place to go and ask questions. It is not evidence of illegal construction. (what I tried)
  • Cameras, police stations, footways, crossings were mapped by OpenStreetMap volunteers. They are generous but incomplete. If it isn't on the map, it may still be on the street.
  • Liquor vends come from official lists, mostly with approximate positions, and the lists are incomplete. Counts near a zone are a hint, not a finding.

A safe way to say it: “Mapped data suggests… but the figures are approximate and unconfirmed.”

Do not publish as findings

Prototypes and unverified data

  • The district iRAD page is unfinished. Some rows were read from scanned PDFs and nobody has checked them against the originals yet. iRAD also counts differently from the traffic police report. The page covers only part of what the district sites publish (113 further reports are listed but not loaded), and some districts publish nothing. Please don't set the two side by side.
  • The 2025 crime counts in the repository come from news reports of Delhi Police data, and I found no police table behind them. There is no district-wise 2025 data and no full-year 2025 IPC/BNS total, and NCRB's 2025 report isn't out. If you need 2025, cite the original news story or ask Delhi Police for the table.
  • Sidewalk coverage near crash zones only shows how little has been tagged on OpenStreetMap. Please don't write that there are "no sidewalks near crash zones". Nobody has measured that, and the data cannot tell you.
  • The 3D pages are for exploring and getting curious. They are not for quoting.

If you are a researcher

You are exactly who I hoped would find this. Here is where to start and where to be careful.

  • Start with the yearly releases. data/releases/ has one folder per year (2016–2024), each with normalised CSV and JSON and a manifest that names the source agency and page. The code is MIT-licensed and the data keeps its original licence. Please read the licence note before reusing a layer.
  • Cite it properly. CITATION.cff says how to cite the repository. For any single figure, cite the agency report as well, because this repository is a copy, not the source.
  • Check the revisions. The data changelog lists every figure I have corrected, with the old value, the new value and why. If you worked from an earlier version, look there first.
  • Reproduce it. Every derived file has a script in scripts/, and most have tests. The README explains the pipeline and the example notebook in notebooks/ shows one way in. If you can't reproduce a number, I want to know.
  • Staged, not published. Material under data/releases/2025/ and data/derived/irad_monthly/ is there for review. It has known gaps (iRAD notes). Treat it as raw material, never as a finished dataset.
  • Mind the limits of the units. Fifteen police districts hide very large differences between neighbourhoods, and small counts swing a lot from year to year. Zone coordinates are approximate, so any spatial join to a zone inherits an error of up to a kilometre. Mapped infrastructure measures mapping effort as much as the street.
  • Missing data is not zero. Where a value is null, it is null for a reason written in the manifest. Please don't fill it in quietly.
  • Tell me what you find. If you spot an error, or you publish something that used this, open an issue. Corrections are logged, and I would like to learn from them.

Before you publish

  • Open the dataset's manifest.json to find the original source and its date.
  • Look at the data changelog for any revision to the figure you are using.
  • Don't compare series that count different things: traffic police crashes, iRAD, and news-reported totals.
  • Found an error? Open an issue on the repository. Corrections are logged in the changelog.
